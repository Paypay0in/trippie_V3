# FEATURES.md — 功能表

這份表只回答一個問題：**哪些行為是 Founder 驗收過的，以及有什麼東西擋得住我明天把它弄壞。**

它不是變更紀錄（那是 git log），也不是待辦清單。

## 規則

1. **狀態只有兩種**：`進行中` 和 `結案`。
2. **沒有測試不准標結案。** 「釘住它的測試」那一欄空著，就代表「我說它做完了，但沒有任何東西擋得住我明天改壞它」。**那一欄本身就是誠實度報表。**
3. **結案不等於不能改。** 程式會被旁邊的新功能、重構、別的缺陷碰到。要凍住的是**行為**，不是檔案。
4. **碰到結案功能的行為，我必須在那次回報裡明寫「我動到了 X，理由是 Y」**，而且只有兩種正當理由：**它錯了**，或**Founder 叫我改**。
   「為了新功能方便」不是理由。
5. **狀態由 Founder 改，不由我宣告。** 我只填「待驗收」；他說一聲才變成 `結案`。
6. 行為描述盡量用**他驗收時說的那句話**，不是我的技術說法。

## 這份表現在長什麼樣子

**大部分是「待驗收」，不是結案。** 那是真的：Founder 看過畫面不等於他說「這條行為從今天起凍住」。
